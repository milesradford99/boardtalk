# Spike S0 results: the board keeps details, but it barely compresses

Run 2026-10-24/25 on the Volcengine Ark agent plan (see the run deviations in `s0-plan.md`):
10 Nebius OpenHands trajectories, 3–5 forced folds each, 199 valid hindsight questions about turns
before the second fold. Total: 38.1M tokens, 89% of them prompt-cache reads by the scribes. Raw
numbers: `spikes/s0/report.md` (regenerated by `grade.py`).

## Headline

| arm | recall | identifier | decision | dead end | state | context kept for the compressed part |
|---|---|---|---|---|---|---|
| raw (ceiling) | 96.5 | 96.0 | 98.0 | 98.0 | 94.0 | 36.1k tok (100%) |
| summary (baseline) | **60.1** | 70.0 | 74.0 | **32.7** | 63.0 | 2.0k tok (5.6%) |
| board, `deepseek-v4.1-flash` scribe | **97.5** | 96.0 | 99.0 | 95.9 | 99.0 | 34.3k tok (**95%**) |
| board, `deepseek-v4-pro` scribe | **95.2** | 96.0 | 95.0 | 94.9 | 95.0 | 21.9k tok (**61%**) |

The board arms beat the summary on all 10 trajectories (summary range 22.5–87.5%, board range
80–100%).

## Against the pass criteria

| Criterion | flash board | pro board |
|---|---|---|
| ≥ summary overall, and no category worse by > 5 pts | ✅ (+37 pts) | ✅ (+35 pts) |
| identifier hallucination ≤ 1% | ❌ 2.9% strict; 1.7% with no near match in the source | ⚠️ 2.7% strict; ✅ **0.8%** with no near match |
| prefix property on 100% of folds | ✅ | ✅ |
| (added) scribe turns lost after retry | 19 of ~830 (2.3%) + 1 handoff | 0 |

By the plan's rule ("if only the strong scribe passes: the design holds, but the scribe cost goes
up"), **the pro scribe passes and the cheap one does not.** The strict hallucination numbers include
formatting drift, such as an added `722:` line-number prefix or changed quote style. The
"no near match" numbers count strings with no ≥70% contiguous match anywhere in the source: likely
reconstructions, for example `IndexError: list index out of range` when the source has
`IndexError` and `list index out of range` apart.

## What this does and does not show

1. **The board keeps what summaries drop, especially dead ends** (95% vs 33%). Rewritten summaries
   condense away failed attempts and why they failed. That is exactly the knowledge that stops an
   agent from repeating itself, and exactly what an append-only record keeps by construction.
2. **But the board is not yet a compressor.** The flash board is 95% the size of the raw text it
   replaces (sometimes larger than raw). The pro board is 61%. The summary is 5.6%. So most of the
   recall gap could be **size, not structure**: the answerer simply had 11–17× more text. **S0
   does not show that a board beats a summary at equal token budget.** This is the open question
   for ADR 0001.
3. **The append-only serialization is very cache-friendly in practice.** 93% (flash) and 90% (pro)
   of scribe input tokens were cache reads, and the prefix property held on every fold.
4. **A per-turn scribe writes a lot.** 975 cards (flash) / 810 (pro) for ~830 turns. The cheap
   scribe wrote more, longer cards, and 1.5× the total tokens of pro.

## Issues found in the harness (fixed and disclosed)

- **Summarizer role-play.** On 2 of 10 trajectories the baseline summarizer once emitted a fake
  agent tool call instead of a summary (251 and 291 chars). That silently wiped the history for
  every later fold. Fix: retry-on-invalid with the same prompt (must contain `<summary>`, no fake
  tool call, ≥1,500 chars). Both trajectories were regenerated, then re-answered and re-judged. The
  baseline went from 56.8% to 60.1%. Other trajectories were unaffected by the policy.
- **The same role-play hit JSON calls** (handoff). Fixed before the full run by ending every call
  with "you are not the agent; respond only via `emit`".
- **Verbatim check false positives** from JSON-escaped quotes and newlines. The check now runs
  against the task, the rendered turns and the decoded tool-call arguments.

**Spot checks by hand:** 15 of 16 sampled judge grades agree with my own reading; 1 was lenient
(closer to partial). Identifier questions were graded by exact match, without the judge.

## Caveats

- n = 10 trajectories from one scaffold (OpenHands, Qwen3-Coder runs) and one domain (Python
  bug-fixing).
- Questions were written by `kimi-k3` from the full raw transcript. Detail-recall questions
  naturally favour a detailed record. This measures memory, not task success; S2 measures task
  success.
- The trajectories contain no hidden reasoning, so the handoff card is a pessimistic stand-in.
- All writer models are DeepSeek. Scribe conclusions hold for these models; Claude scribes are
  untested.

## Recommendation

Keep ADR 0001's direction. Before building on it, run **S0b: equal-budget comparison**. Give the
board a token budget (e.g. 2k / 5k / 10k for the compressed part) using a second-level fold
(cards → page digests), give the summary the same budgets, and re-score with the same questions
and answers pipeline. That reuses everything S0 built, and it answers the one question S0 leaves
open. If the board still wins at equal size, the structure is doing the work. If it only wins
when larger, the ADR's value case shrinks to "a better record, at a token cost".
